# 部署手册

> 说明：本文是 RAG 检索的演示语料，场景与数据均为虚构。

## 环境与流程

生产环境使用 pm2 托管 Node 服务，部署脚本位于 `scripts/deploy.sh`。标准流程是：
拉取代码 → 安装依赖 → 构建 → 重启进程 → 健康检查。

重启命令为 `pm2 reload super-agent`（平滑重启，不断连接）。

## 上次部署事故记录（2026-08-14）

事故现象：线上服务在发布后 12 分钟内出现 502，约 30% 的请求失败。

根因：发布脚本里用的是 `pm2 stop super-agent && pm2 start super-agent`，
stop 与 start 之间有几秒空窗，此时请求全部打到已停止的进程上。
同时健康检查配置的超时是 3 秒，比 pm2 的启动时间还短，导致健康检查先报了失败。

修复措施：
1. 把 `pm2 stop && pm2 start` 改成 `pm2 reload`（平滑重启，零空窗）；
2. 健康检查超时从 3 秒调到 10 秒，并加上 3 次重试；
3. 发布脚本增加一步：reload 后轮询 `/healthz` 直到返回 200 才算成功。

## 回滚策略

保留最近 3 个版本的构建产物。回滚命令：`./scripts/deploy.sh --rollback <version>`。
回滚不需要重新构建，直接切换软链并 reload，平均 20 秒完成。

## 数据库迁移注意事项

改表结构必须在低峰期执行，且要先在预发环境跑一遍完整迁移。
迁移脚本必须可重复执行（幂等），并且准备好对应的回滚脚本。
