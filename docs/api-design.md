# API 设计规范

## 命名与版本

REST 接口统一以 `/api/v1` 开头。资源用复数名词（`/users`、`/orders`），
动作用 HTTP 方法表达，不要在路径里出现动词。

版本升级通过路径前缀切换，不做 header 协商——路径更直观，便于灰度。

## 错误处理约定

所有错误响应统一结构：

```json
{ "error": { "code": "USER_NOT_FOUND", "message": "用户不存在", "requestId": "..." } }
```

要点：
- `code` 是稳定的机器可读标识，客户端据此做分支；`message` 只给人看；
- 永远返回 `requestId`，方便日志串联排查；
- 4xx 是调用方问题（参数、权限），5xx 是服务端问题。**不要把可预期的业务失败做成 5xx**。

## 超时与重试

服务间调用默认超时 3 秒；写操作不自动重试（除非接口支持幂等键）。
读操作可以重试 2 次，采用指数退避并加抖动。

## 分页

统一用游标分页（`?cursor=xxx&limit=50`），不用 offset——offset 在数据变动时会漏数据。
响应里返回 `nextCursor`，为空表示没有更多。
